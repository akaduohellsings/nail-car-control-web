# 独立导航页面与接口预留

## 文件与入口

- `navigation.html`：独立导航页面，由原手动页顶部入口打开。
- `navigation.css`：导航页面布局，桌面左右分栏、窄屏上下排列。
- `navigation.js`：目标草稿、连接设置、操作记录；仅使用浏览器本地存储。
- `navigation-api.js`：导航服务适配器预留，当前不实现网络通信。
- `index.html`：只增加导航页链接，原 `app.js`、`styles.css` 未修改。

## 当前能力

可填写 X/Y（米）与朝向（度），保存、刷新恢复或清空草稿；可保存 HTTP/HTTPS 服务地址。地址尚不决定真实端口、路径或 ROS 通信方式。地图、位置、任务状态保持未知，所有实车操作禁用。

草稿只是坐标，尚未绑定地图，后续必须选择当前地图并重新确认目标，不能自动发送旧草稿。切换原手动页面只是网页跳转，不能代替实际取消导航与控制权接管。

## 后续接口边界（待后端确认）

适配器提供 `connect`、`getStatus`、`getMap`、`subscribeStatus`、`start`、`pause`、`resume`、`reset`、`requestManual`、`releaseManual`、`stop`、`disconnect`。当前异步方法统一拒绝并报告未接入；订阅为空，`implemented` 为 false。替换适配器并完成状态处理前，不能启用按钮。

导航目标应包含 request_id、map_id、地图坐标与朝向；界面使用度，后端接入时明确与 ROS 弧度/四元数的转换。状态回传应包含时间戳、任务编号、FSM 状态、控制权、控制代次、停车确认、定位有效性、故障原因和清理尝试次数。地图应包含版本、坐标系、分辨率、原点、宽高及栅格数据。

开始导航需服务在线、状态新鲜、地图和定位确认、目标绑定地图。手动接管必须经过取消确认和停车确认，手动退出不自动恢复任务。网页停止的处理结果必须由后端确认，不能仅凭请求成功展示已停止。

后续先接入地图与状态的只读数据，再接入单点导航、暂停恢复与手动接管。多点巡航留到单点与协调机制实车验证后。
