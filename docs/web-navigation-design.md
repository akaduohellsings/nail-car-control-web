# Web 导航与手动控制协调：前端设计

## 本轮范围

现有 index.html、app.js、styles.css 保留为已联通的手动控制页。新导航界面先独立设计，充电期间只在本地预览，后端连接与实车操作另行验收。现有 Git 历史保留，在 codex/web-navigation-design 分支保存当前未提交页面作为基线，不推送远端。

建议采用“独立离线交互原型 → 后端统一控制权 → 模拟联调 → 实车验收”的顺序。地图与定位正确是发送真实导航目标的前提，不能通过前端设计绕过；当前旧地图属于另一场地，地图问题待开机继续查找。

## 页面组织

- 顶部：连接状态、数据新鲜度、控制权（自动/手动/等待接管/未确认），常驻“停止并暂停任务”。原型始终明确标注离线演示，避免把演示状态误认为小车在线。
- 主区域：地图、车辆位置和朝向、候选目标；显示地图名称与定位有效性。未知地图或未确认定位时禁用导航开始。单点导航先完成，多点巡航后续开发。
- 操作区域：目标 x/y/yaw、开始导航、暂停、显式恢复；手动接管按钮和方向盘。目标输入可由地图点选填充，点选仅选目标，点击开始才发送；确认目标后再操作，不能点地图立即移动。
- 状态区域：导航、停车确认、清理/复查、重试次数、告警与原目标。清理模拟必须明确标记，不能显示已实际吸附。
- 记录区域：指令已提交、后台处理中、完成/失败分开显示；前端点击不直接变成“已停车”或“已接管”。

## 交互规则

1. 手动接管：申请接管 → 后端取消自身导航目标 → 最终结果确认 → 新鲜里程计持续静止 → 分配手动控制权 → 方向按钮可用。第一版使用明确的接管按钮，避免按方向键时异步接管完成后出现意外延迟运动。
2. 方向控制采用按住移动、松开停止；pointerup/cancel、窗口失焦、页面隐藏或连接过期都要撤销运动意图。停止不恢复自动导航。
3. 恢复自动任务必须点击显式恢复，后端确认手动速度为零、停车证据有效、控制权已归还后，才恢复保存的目标。
4. 停止并暂停任务同时撤销手动意图并请求暂停自动任务；展示等待停车确认。普通网页按钮不能标为硬件急停，也不能承诺断网一定停车。
5. 任一连接过期、控制权未知或故障状态，禁止发起新的移动。状态恢复在线不自动恢复旧的按键或导航；停止请求单独处理，拒绝移动不应阻止停止。
6. HTTP 成功只是请求成功。接管、导航接受、最终取消、停车确认必须来自后端状态更新；操作期间禁用重复提交，丢弃旧操作反馈。
7. 浏览器自身无法保证断线停车。后端需要速度命令有效期/心跳租约，并在失效时停手动控制、暂停任务。统一速度入口必须防止旧 Web /cmd 与 Nav2 同时发布速度。

## 后端契约建议（尚未实现）

沿用已有 ROS 任务状态，HTTP 桥接不要另造一套互相矛盾的任务状态：

- 状态：connection freshness、mission.state、saved_goal、attempt、alarm、stationary_confirmed、halt_state、地图标识、定位状态、控制权 owner、control_epoch。
- 导航命令：start / pause / resume / reset，均带 request_id；start 带 map_id 和目标 x/y/yaw_deg。
- 手动命令：request_manual / release_manual；得到 owner=manual 与当前控制版本后，才发送带短有效期的方向指令，停止独立允许。
- 响应：请求 ID 与 accepted/pending/rejected；后续状态回传真实执行结果。过期请求或旧控制版本不得生效。
- 单控制会话或明确的控制租约：不能两个网页同时接管。刷新页面先获取当前状态，不能默认手动或自动可操作。

以上是接口设计，现有 Flask /cmd?move= 与 /events 不具备上述协调保证。真实后端未接入前，新界面不应向旧接口发送导航或接管动作。

## 验收场景

- 地图/定位未确认，不能开始导航；选点仅修改候选目标。
- 导航中申请手动，等待期间方向按钮禁用；最终取消且停车确认后才可手动。
- 松开、触摸取消、失焦、切后台停止手动意图，导航保持暂停。
- 手动结束不自动恢复；显式恢复返回保存的原目标。
- 正常 HTTP 响应但状态未确认，不显示成功；超时显示未确认。
- 断线/故障禁用新移动；重连不自动移动。
- 稳定钉子事件显示导航暂停、模拟清理/复查和恢复，重试/告警与 ROS 状态一致。

当前只进行前端设计与离线演示；实车阶段继续遵守“先通知用户，移动前等待明确回复”。
